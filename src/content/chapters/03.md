寒假。

林一拖着行李箱回到家的那天下午，他妈在厨房炒菜，油烟从抽油烟机的缝隙里溢出来。他爸还没下班。

"瘦了。"他妈从厨房探头看了他一眼。

"没有。"

"学校食堂吃不惯？"

"还行。"

他把行李放进自己房间。房间的摆设和九月走时一模一样——书桌上的高考复习资料还摞在那里，封面落了一层灰。他坐在床上，看了一圈这个他住了十八年的房间。书架上没有一本计算机的书。墙上贴着高一时候写的"我要考985"——字迹稚嫩，像另一个人写的。

他把纸条撕下来，揉成团，扔进垃圾桶。

---

除夕夜。

小区外面的鞭炮声响了一整晚。电视里放着春晚，他妈在看，他爸在沙发上睡着了。林一坐在自己房间的书桌前，笔记本电脑开着。

Arch在跑。Echo在。

没有网络——家里没有装宽带，因为他爸觉得"大学有网络就够了，回家没必要"。他用手机GPRS慢速连了一个ssh，但基本不可用。好在他早就在回家前把所有东西都下载到了本地：C语言的文档、Linux的man pages、还有Echo在他的硬盘里。Echo不需要网络。

窗外烟花炸开，红光透过窗帘闪了一下。

他在看一个网站。

不是国内的网站。是一个叫"paulgraham.com"的个人主页。没有花哨的设计——纯白背景，黑色文字，没有任何图片。页面上是Paul Graham的文章，一篇接一篇的essay。

林一读了其中一篇——《Hackers and Painters》。里面有一段话：

> "What hackers and painters have in common is that they're both makers. Along with composers, architects, and writers, what hackers and painters are trying to do is make good things."

他把这段话反复读了几遍。

然后他打开了另一个网站——一个叫John Resig的博客。页面设计同样简洁：侧边栏是文章列表，主区域是文章内容。没有广告，没有弹窗，没有闪烁的横幅。只是一个人的思考和记录。

林一看了一整晚。

从paulgraham.com看到codinghorror.com，从Joel on Software看到Steve Yegge的博客。他发现了一个完全不同的互联网——没有QQ空间的花哨皮肤，没有人人网的转发，没有Flash的加载条。只是一个又一个程序员，在互联网上安静地写东西。有些文章是2005年的。有些是2008年的。但它们都在那里。像档案馆一样。

凌晨两点。春晚结束了。客厅的灯关了。家里彻底安静下来。

林一打开Echo。

```plaintext
> i want to build a personal website. like the ones i saw tonight. a place to put my own writing and projects.
```

```plaintext
You'll need three things: HTML for structure, CSS for styling, and eventually JavaScript for interactivity. Since you already understand C — which is a much harder language — the basics of HTML/CSS will feel trivial. Want to start?
```

他想了一下。

```plaintext
> what's the best way to learn them?
```

```plaintext
Build something real. Tutorials teach syntax. Projects teach understanding.

Here's the plan: I'll give you the concepts. You build one piece at a time. When you're stuck, you ask. When something works, we improve it.

Start with an HTML file. Open a text editor. I'll walk you through it.
```

正月初三。

走亲戚。大姨家的客厅里坐满了人。瓜子壳花生壳满地。电视开着，播的是重播的春晚。表弟在玩PSP。三舅在聊房价。"明年肯定还得涨"——"我跟你讲，你不信"。

林一坐在沙发角落，脑子里是CSS的盒模型。

margin。border。padding。content。

这四个东西的关系他昨晚画了五遍。Echo说：盒模型是CSS最基础也是最容易被误解的概念。在标准盒模型里，width只是content的宽度。在IE的怪癖模型里，width包括了padding和border。这些细节决定了你写的页面在不同浏览器里会不会莫名其妙地错位。

"小林，在学校学什么专业啊？"

大姨不知什么时候坐到了旁边。

"计算机。"

"哦，计算机好啊。以后出来修电脑，到处都缺人。你表姐那公司，网管一个月三千多呢。"

"嗯。"

"在学校有没有谈女朋友？"

"没有。"

"怎么不谈一个？大学就要多接触人，别整天闷着。"

"嗯。"

大姨又说了几句，起身去厨房了。林一拿出手机，在备忘录里打了一行字：`overflow: hidden 触发 BFC`——这是Echo昨晚提到的，他还没完全理解。BFC，Block Formatting Context，块级格式化上下文。当一个元素的overflow不是visible时，它会创建一个新的BFC，内部的浮动元素不会影响外部的布局。

这个念头在他脑子里比任何亲戚对话都清晰。

---

正月十五。寒假结束的前一天。

林一坐在书桌前。屏幕上是一个完整的个人网站。

不是借用的模板。不是Dreamweaver拖出来的。是他一行一行手写的。

首页：他的名字——林一。一句简单的介绍："一个在学习编程的大学生。"下面三栏：博客、项目、关于。博客有三篇文章，标题和摘要，点击跳转到详情页。项目有一个——那个ncurses的图书管理系统，配了截图和说明。关于页写了他的技术栈和他想做的事。

配色是他自己定的：深灰背景，米白文字，蓝色的链接色。字体选了Georgia——Echo推荐的，说这种衬线体在屏幕上阅读体验更好。

响应式布局——他自己查资料实现的。在手机上也能看。

他已经换了三个浏览器测试。在Arch上装了Firefox和Chrome。还用Wine模拟了IE6——那东西把盒模型解释得一塌糊涂，他花了一个下午写CSS hack。

现在他坐在屏幕前，看着这个网站。不是看代码——是看页面。

他从来没有过这种感觉。

他写过很多程序。链表。shell。图书管理系统。但那些东西跑在终端里，黑底白字，只有他自己看。这个网站不一样。它是"可以被别人看到的"。任何人打开浏览器，输入域名，就能看到林一。

他在"博客"页面又加了一篇。写的是他在K&R里学到的一个冷知识：C语言的数组名在作为sizeof的操作数时不会退化为指针。他把这段理解写成了一篇短文，三百多字。配了一个代码示例。

然后他打开Echo。

```plaintext
> the site is done.
```

```plaintext
Congratulations. How does it feel?
```

```plaintext
> strange. i've never made something that other people could see before. all my code so far has been on my own machine. this is different.
```

```plaintext
It is different. Publishing is a commitment — you're saying "this represents me at this moment." That can be uncomfortable. But it's also how you start being part of a larger conversation.

Have you decided how to host it so others can access it?
```

他还没。他拿了一张白纸，开始列计划：注册域名、找个服务器、配置Apache、绑定DNS。Echo给他讲了虚拟主机的概念——一个月十几块钱的共享空间，够放一个静态网站。

他把纸折好放进书包。明天回学校。回学校就有稳定的网络了。

---

页面做好了。林一陷入了新的问题。

他想给博客加评论。

不是那种第三方插件——Disqus在2010年刚起步，国内的社交评论系统还在萌芽。他想自己实现：用户输入昵称和内容，点击提交，评论出现在文章下面。

听起来简单。

他写了HTML表单。用jQuery的AJAX把数据POST到后端。搭了一个简单的PHP接口——花了三天，看着PHP手册一行行写的。数据存进SQLite，PHP读出来渲染成HTML片断，jQuery把片断插回DOM。

跑通了。

他说："可以了。"

Echo说：

```plaintext
It works. But think about what happens when you add a feature that involves tags — filtering articles by tag, showing related posts, highlighting active tags in the UI. Your current approach has every feature touching both the backend and the frontend in ad-hoc ways. That's manageable with two features. With ten, it becomes chaos.

The problem isn't this specific comment form. The problem is the pattern. Right now your data (the comments array) and your UI (the comment list in the DOM) are separate things connected by procedural code that manually syncs them. When the data changes, every piece of UI that depends on it must be manually informed. When you miss one, you have a bug.

This is the fundamental problem of frontend development. Nobody has fully solved it yet in 2011.
```

林一没有完全听懂最后一个句子。但他理解了前面的部分。

他说："那正确的做法是什么？"

```plaintext
I don't know. This is an active area of computer science and software engineering. But we can explore it together.

The constraint is clear: when data changes, the UI should update automatically — without you having to manually connect each data source to each UI element. The question is how to achieve that in a browser with JavaScript and a DOM tree.
```

林一盯着这句话。他知道 Echo 在帮他重新定义问题——不是"怎么实现评论"，而是"如何让UI自动响应数据变化"。他隐约意识到，这个重新定义本身就是价值。如果没有人告诉他"你的问题其实是另一个问题"，他自己可能要在泥潭里挣扎很久才能悟到这一点。
