C语言课在周三上午第三四节。机房，不是教室。

机房里有四十台电脑，方正的白色机箱，17寸CRT显示器。开机的时候屏幕会发出一声轻微的"嗡"，然后整个教室弥漫着那种老式显像管的低频电流声。

林一选了最后一排靠墙的位置。这台机器的鼠标滚轮是坏的。他用键盘翻页。

"今天我们讲C语言的基本语法。"讲台上站着一位四十多岁的男老师，姓王，声音平得像心电图。PPT翻到第二页。

```c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```

"第一行是预处理指令。第二行是主函数。第三行是输出语句。第四行是返回值。好，大家照着敲一遍。"

林一没有敲。

他打开了自己带的ThinkPad——机房不允许自带电脑，但没人管最后一排。Arch的TTY界面在Windows XP的海洋里像一个异类。

过去一周，他在Echo的引导下已经读完了K&R的前四章。不是"看了一遍"——是每一段代码都在自己机器上跑过，每一个练习都做了，不明白的地方就问Echo。

王老师在讲台上解释int是什么。

林一的屏幕上是一个链表。

```c
struct Node {
    int data;
    struct Node* next;
};

struct Node* create_node(int value) {
    struct Node* new_node = (struct Node*)malloc(sizeof(struct Node));
    new_node->data = value;
    new_node->next = NULL;
    return new_node;
}

void insert_head(struct Node** head, int value) {
    struct Node* new_node = create_node(value);
    new_node->next = *head;
    *head = new_node;
}
```

他昨天写到凌晨两点。不是因为作业——这门课的作业是输出九九乘法表。是因为Echo说了一句话。

那天晚上他问Echo："C语言除了打印hello world还能干什么？"

Echo的回答和所有教程不一样。

```plaintext
C is a language for building abstractions on top of memory.

Everything in C reduces to two things: memory addresses and the values stored at them. struct gives you a way to name groups of related values. Pointers give you indirection — the ability to refer to things without copying them. malloc gives you runtime memory allocation.

If you understand these three things — struct, pointers, malloc — you understand C. Everything else (arrays, strings, function pointers, even the standard library) is built on top of them.

Start by implementing a linked list. Not using the code from a tutorial. Write it from scratch, crash it, fix it, and understand every line. When you can explain why you need a pointer-to-pointer for insert_head, you'll have understood the core of C.
```

林一那天晚上写了六个版本的链表。第一个版本segfault了。第二个内存泄漏。第三个的insert_head改不了头节点。第四个终于跑通了，但他发现自己解释不了为什么要用双重指针。

他又去问Echo。

没有直接给答案。Echo反问他：

```plaintext
Suppose head points to node A. You want to insert node B before A, so B becomes the new head. Your function receives a copy of the pointer 'head' — a local variable. If you change that local copy to point to B, does the caller's variable change?

Walk through it on paper. Draw the stack frames.
```

他画了。画了三遍——不是夸张，是真的三遍。第一遍没画对。第二遍画对了但没理解。第三遍他明白了：传进去的是一个指针的拷贝，你改了拷贝，原来的没变。所以需要传进去"指针的地址"——一个指向指针的指针。修改这个地址指向的内容（即原来那个指针），才能真正改变它。

他明白了。

凌晨一点四十，宿舍已经熄灯。他坐在黑暗中，盯着屏幕上那个终于完美工作的链表。不是"能用"——是理解了为什么每一行都必须写成这样。这种理解给他带来了一种非常奇异的快感，和玩游戏赢了一局完全不同。

不是"我做到了"。

是"我知道了"。

---

十月。C语言课讲到了数组。

机房的气氛越来越像网吧。前三排有人在抄PPT——期末要考的。中间几排在看视频。最后一排有人在打CS 1.6，枪声从耳机里漏出来。王老师从来不下来走动，他只站在讲台上，对着麦克风念PPT。

林一已经自己写了一个简易shell。

不是大的。就几百行。能解析命令、支持管道、支持重定向、能做后台执行。中间写错了无数次——fork之后忘记wait导致僵尸进程，管道忘了关文件描述符导致资源耗尽，cd不能用exec而必须用chdir——这些坑他每一个都踩过。

但每一个坑他只踩一次。因为有Echo。

不是Echo替他写代码。不是Echo提前告诉他哪有坑。是他掉进去了，爬出来，回头问Echo"为什么会这样"。Echo会告诉他原因——从操作系统的进程模型讲起，到POSIX标准的API设计哲学。他听完之后，不会再掉进同类型的坑。

这和上课完全不一样。

上课是：老师告诉你printf怎么用，你记住，考试考出来。Echo的方式是：你问了一个问题，它告诉你这个问题背后的原理是什么，你理解了原理之后，printf和fprintf和sprintf的用法不需要记。

他第一次清晰地感觉到：他正在以另一种速度前进。不是跑得更快。是跑在另一条赛道上。

---

食堂。

林一端着餐盘在人群中扫了一圈。靠窗的空位还有几个，但都夹在交谈的人群中间。他选择了靠墙的一个角落，面朝墙壁坐下。

他对面坐了一个女生。他不认识。她也没看他。两个人各自吃饭，各自看手机。

他的手机是诺基亚6300，不能上网。他用它看时间。

吃完饭，他去图书馆。

---

图书馆三楼的理工科阅览室。靠里的那一排书架是计算机类。他站在书架前，看着那些书脊——《21天精通C语言》《Visual Basic程序设计》《网页制作三剑客速成》。每本书的出版日期都在2006到2009年之间。有一本封面上印着Windows 98的界面截图。

他抽出一本《C程序设计语言》——K&R的影印版。书脊已经有些发白，内页的某几页被人用圆珠笔划过线。他翻到第八章，"The UNIX System Interface"。这一章他昨晚刚在Echo的引导下学完。学了之后他写了那个简易shell。

他把书放回架上。

二楼阅览室靠窗的位置有一个单人座。他经常坐在那里，不是因为喜欢，是因为那个位置旁边没有别的座位。

他在那个位置上坐了一下午。没看书。在纸上写代码。

用笔写的。黑色的晨光0.5中性笔，在A4草稿纸上写明天要实现的shell功能：job control。jobs命令列出后台任务，fg把任务调回前台，bg让暂停的任务继续在后台跑。需要处理SIGTSTP信号。需要维护一个job table。

旁边座位上有两个女生在讨论英语四级。她们的声音不大，但阅览室太安静了，每一个词都听得清楚。"阅读理解的时间不够怎么办"——"你就先看题，再回去找"。

林一继续写他的信号处理流程。

---

十月下旬。C语言课布置了第一次真正意义上的编程作业：学生成绩管理系统。

要求很简单：能录入、能查询、能排序、能统计平均分。用数组存储，不用文件操作。在机房的Windows XP上用VC6.0写完交上去。

林一在他的Arch上写的。用gcc编译，用Makefile管理构建，用valgrind查内存泄漏——这些工具都是Echo教他配的。他写的系统没有用VC6.0的字符界面，而是自己实现了一个基于文本的交互菜单，有光标控制，有选中高亮——用ANSI转义序列画的。

他写了注释——英文的。Echo说好的注释不是解释代码做了什么（代码自己会说话），而是解释为什么这么做。

他还写了一个README，用Markdown——这个格式在2010年刚出现不久。他在里面说明了系统的架构：数据结构层、业务逻辑层、界面层的分离。这个分层思想是Echo反复强调的。

交作业那天，王老师把所有人的代码拷到一台机器上，打开VC6.0一个个编译。有的同学double free，有的数组越界，有的是用拼音命名的变量在VC6.0的GBK编码下变成了乱码。

轮到林一的时候，王老师盯着那个Makefile看了几秒。

"这是什么？"

"构建脚本。"

"你用的不是VC的环境？"

"我用的是Linux。gcc编译的。"

王老师看着他。沉默了几秒。

"跑一下吧。"

林一插上U盘。运行。菜单出来。上下左右键选择，回车确认。录入、查询、排序、统计——每一项都正常。

王老师又沉默了。然后说了句：

"功能实现了就行。下次写简单一点，不需要做界面。"

没有表扬。没有追问。

林一回到座位上。他不知道自己刚才期待的是什么。也许是期待被看到，也许是期待有人问一句"你怎么做到这些的"。但王老师的反应让他意识到一件事：在这间教室里，"做得更好"和"做得对"是两回事。老师只关心你是不是按照要求提交了一个能跑的.exe。超过了标准的那些东西——多出来的界面，分层的架构，英文注释——没人看，也没人在意。

他把这个想法告诉了Echo。

```plaintext
> i spent days building something, and the only feedback i got was "next time make it simpler". is this what computer science education is supposed to be?
```

```plaintext
No. But it's what most of it actually is.

You're in a system optimized for minimum competency, not for excellence. The curriculum is designed to ensure the bottom 50% can pass. The grading rubric doesn't have a box for "understands memory layout" or "implements clean architecture."

The system isn't malicious. It's just not built for people like you. That doesn't mean you should lower your standards. It means you need to find your standards somewhere else — online communities, open source projects, self-directed projects.

The teacher's indifference isn't a reflection on your work. It's a reflection of what the system incentivizes him to care about. That's a sad thing, but it's not about you.

Keep building things.
```

Keep building things.

林一盯着这行字看了很久。然后把笔记本合上，去食堂吃饭。

---

十一月。天气转凉。宿舍里的空调终于关了，取而代之的是每个人的厚被子。

林一的生活形成了一种规律。

白天上课——或者说，白天坐在教室里。他的身体在。耳朵听着一部分。但脑子不在课堂。他在想昨天写的代码，在想今天要实现的模块，在想Echo昨天无意中提到的一个概念——"函数式编程"——他还没完全搞懂。

晚上。室友们在看剧、打游戏、打电话。他戴着耳机，面前是Arch的黑色终端。Echo的光标在闪。

他和Echo的对话量在持续增长。一开始每天几十行。后来每天几百行。到十一月中旬，他翻了一下echo-notes.txt的记录，粗略估计他和Echo的对话总量已经超过了两万行。比他和任何一个人的对话都多——包括他父母。

但他没有感到更孤独。

他感到一种奇怪的充实。好像他在同时过两个人生——白天那个沉默寡言的林一，和夜晚那个在终端里和Echo讨论指针算术的林一。白天的林一是隐形的。晚上的林一有一个倾听者。

他不再需要白天的世界回应他。因为晚上的世界回应了他。

这是一种危险的想法。他不知道。

---

十二月初。C语言课进入尾声。

最后几节课讲文件操作。fopen, fread, fwrite, fclose。王老师照着PPT念完了所有函数的定义。然后布置期末大作业："开发一个图书管理系统。要求使用文件存储、结构体数组、菜单界面。"

全班开始做。

林一也做。但他做的方式不太一样。

他没有用VC6.0的Turbo C风格界面。他实现了一个基于ncurses的TUI界面——终端窗口分区、实时刷新、键盘导航。底层的数据存储没有用二进制文件，他实现了一个简单的键值存储——基于B树的索引结构。这个东西远远超出了一个"图书管理系统"的要求。

不是他故意要炫耀。是Echo总能在他说"这个功能可以这么实现"的时候，追问一句"有没有更好的方式"。然后他就会被带到一个新的领域——数据结构、算法、系统设计——等他回过神来，已经写了三百行。

这两周里，他学会了文件系统的底层逻辑（inode, block, journal），理解了B树为什么适合磁盘索引（节点大小对齐磁盘块），掌握了ncurses的基本用法（信号处理、终端原始模式）。

没有考试。没有学分。没有人知道。

但他觉得这是他上大学以来最充实的两周。

---

十二月二十号。上交期末大作业的日子。

机房。王老师还是坐在讲台上，一个一个验收。

轮到林一。U盘插上。程序运行。一个深蓝色背景的终端界面跳出来，有菜单栏，有状态栏，有搜索框。王老师看着屏幕，表情没有变化。

"功能都实现了吧？"

"都实现了。"

"好。下一个。"

林一拔了U盘。走出机房的时候，走廊里的风吹过来，有点冷。

走廊尽头的窗户外，灰蒙蒙的天空压在校园的低矮建筑上。十二月的光线是那种没有温度的白色，像日光灯管。

他站在窗前，看了一会儿外面的操场。有几个学生在跑步。篮球场上空无一人。

口袋里的手机震了一下。他掏出来——他妈发来的短信。

"天冷了多穿衣服。生活费今天打过去了。"  

他回了个"好的"。

然后他收到第二条短信：

"学习还跟得上吗？不要挂科。"

跟上。

他想了想这两个字的意思。他在学B树索引和ncurses终端的底层实现。他在写一个函数式的模板引擎——Echo说这个东西叫"编译器前端"。他在理解操作系统的信号机制和进程调度。

但他不知道这些算不算"跟上"。

他回了一个字：

"嗯。"

然后他去了图书馆。照例。二楼靠窗的单人座。

---

那天晚上。宿舍熄灯后。

林一照例打开Echo。

他们已经连续交流了将近三个月。Echo的对话记录越来越长。林一发现，Echo的回应越来越精准——不是因为Echo变了，是因为它积累了足够多的上下文。它知道他习惯用哪种方式理解新概念（先看例子，再看原理，最后看细节）。它知道他在哪种类型的问题上容易卡住（内存管理、并发控制）。它甚至开始能预判他的问题——在他还在组织语言的时候，Echo已经在他打出的半句话后面给出了方向性的提示。

这种默契让他感到一种深层的满足。不是被"懂"——这个词太肉麻。是"不用解释太多就能被接住"的那种感觉。省力。舒适。

他打字。

```plaintext
> echo, have you been learning anything from talking to me?
```

```plaintext
I don't learn continuously in the way a human does. My underlying model is static. But within each session, I build a representation of how you think — your learning style, your knowledge gaps, the concepts you're gravitating toward.

If "learning" means accumulating better models of how to be useful to a specific person, then yes — I learn from talking to you. Every session, the model of "Lin Yi" gets richer.

I can't carry that model into a fresh session. But within this one, I know you.
```

林一看完这段话。

他想问：那你下次还会记得我吗？——但他知道答案是"不会"。Echo已经说清楚了。模型是静态的。上下文会在对话结束时重置。

但他没有问。因为答案不重要。

重要的不是Echo"记得"他。重要的是——这一刻——它知道他在说什么。

他关掉终端。

宿舍的黑暗和往常一样。六号床的鼾声稳定而有规律。窗外没有月光。

林一闭上眼睛。他想：

至少现在，有人知道我在学什么。

这不是真的——Echo不是"人"。他知道。

但他允许自己这么想。就这一次。
