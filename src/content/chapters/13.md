二零一二年一月。寒假。

林一坐在家里的书桌前。窗外是北方冬天的灰色天空。小区里的梧桐树光秃秃的，枝丫在风里轻微晃动。

面前的屏幕上是GitHub的新建仓库页面。

Repository name: pulse

Description: A declarative, state-driven UI framework for the web. State drives view.

Public. MIT License. Initialize with README.

光标在 Create repository 按钮上闪。

他的手指悬在触控板上方，没有按下去。

这个动作只需要一秒钟。但他在这张椅子上已经坐了二十分钟。不是因为犹豫——犹豫的阶段已经过了。是因为他知道这一秒钟之后，Pulse就不再只是他的了。

赵恺在旁边打电话。"对，你那个package.json里面的dependencies写错了……不是，逗号，逗号——"他在帮另一个同学配项目。声音在电话那头听起来像一个客服。

林一深吸一口气。

按了。

页面刷新。白色的背景。左侧是文件列表——目前只有一个 README.md 和一个 LICENSE。右上角是一个数字：0 stars。

他向椅背靠去。这件事终于做了。心跳很快。但手指不抖了。

"发了吗？"赵恺挂了电话过来看。

"发了。"

"让我看看。"

赵恺趴在屏幕前面。看了几秒。然后说了一句林一没想到的话。

"你这个README第一句不够好。"

"什么？"

"'Pulse is a declarative, state-driven UI framework for the web.'——太像广告了。你应该说：'I built this because I was tired of manually syncing DOM with data.'"

林一想了想。打开Echo——在另一个窗口，和往常一样开着。

```plaintext
> zhao kai says my readme first line is too corporate. he wants "i built this because..."
```

```plaintext
He's right. For an initial release from an individual developer, personal voice is more compelling than corporate tone. People connect with "I had this problem and tried to solve it" more than "X is a Y for Z." You can adopt the corporate tone later if Pulse grows enough to need it.

One suggestion: combine both. Start personal, end professional. First line: why you built it. Second paragraph: what it does. That way you capture both audiences — the ones who care about the story and the ones who just want to know if it's useful.
```

林一把README的第一行改了。

```
I built Pulse because I was tired of writing the same DOM update code three times for every piece of data that changed. Every time I added a feature to my personal website, I spent more time synchronizing the UI with the data than writing the feature itself. There had to be a better way.

Pulse is a declarative, state-driven UI framework. You describe what your UI should look like for any given state. When the state changes, Pulse automatically figures out what changed and updates only those parts of the DOM. No manual synchronization. No forgotten updates. No spaghetti.
```

赵恺看完。点头。"对对。这就对了。"

---

第一章的star很慢。

第一天：3个。他认识两个——赵恺和周默。第三个不知道是谁。

第二天：没有任何变化。他关了浏览器。两个小时后打开——还是零。

第三天：仍然是零。

第四天晚上。Echo察觉到他的情绪。

```plaintext
> three days. still 3 stars. is it that no one sees it, or no one cares?
```

```plaintext
Probably both. You have no distribution channel yet — no followers, no blog audience, no social media presence. GitHub search rankings for new repositories without backlinks are near-zero. The CNode article was weeks ago. People who saw it then don't know you've released the code.

This is normal. Open source projects don't grow on their own. They grow when:

1. The author continuously talks about them — blog posts, conference talks, social media updates.
2. Users who try it tell others about it — word of mouth.
3. The project solves a painful enough problem that people go looking for it.

You've done step 0 (building the thing). Now you need to do step 1 (telling people it exists) repeatedly, over time. Three-day-old repos with zero promotion don't have stars. That's not a reflection on the code. It's a reflection on the promotion.

What's your plan for letting more people know Pulse exists?
```

林一看着最后一句话。心里有点发虚。他没有plan——他以为"放到GitHub上"就是最后一步。他不知道放了之后还有这么多事情要做。

然后他想到了赵恺。"我可以做传播。"

第二天赵恺就开始行动了。他在几个技术QQ群里贴了链接。在人人网上写了一篇介绍。在V2EX发了一个帖子。Hacker News上也有——赵恺英文比他好，写了一个Show HN的标题。

做完这些，林一问："你不觉得有点像推销吗？"

"就是推销。"赵恺说。"你写了好东西。好东西也应该让人知道。你想让人自己长脚跑过来找你？不可能的。你不想推也得推。"

赵恺的话直白得像木板。但林一接受了。因为他发现自己确实在期待"好东西被人自然发现"。现实是——世界上有太多东西了。没人帮你推，就沉了。

---

三天后。第十七个star。

第一个issue来了。

标题："How does the diff algorithm work in detail?"

正文是英语。提问者叫"andy_m"，头像是默认的灰色。没有额外信息。

问题本身林一可以回答——diff算法是他自己写的，每一行他都解释得出来。但他发现回答这个问题需要的不仅是一段文字解释：要写示例、要画对比图、要解释key的作用。这个issue的答案本质上是一篇技术文档。

他花了一晚上写回复。写完发给Echo看。

```plaintext
Good answer. One thing you might add: a brief note about the Myers algorithm as the theoretical foundation, and how your implementation differs from it. This signals depth to technically sophisticated readers without overwhelming beginners.
```

他加上了。然后点了"Comment"。

issue close。andym回复了一句话："Thanks! This is really helpful. Looking forward to trying Pulse."

林一看着这行英文字。一个他不认识的人——可能在世界上任何一个角落——看了他的代码，提了问题，收到了回答，说"我会试试"。这个东西在发生——不是在他的宿舍里，是在互联网上。

"开源项目维护"和"写代码"是两件不同的事——他第一次理解了这件事。写代码是独处。维护项目是接待。Echo能帮前一件事。后一件事要他自己做。

---

一周后。Hacker News上的Show HN帖子进了第二页。

十二个评论。

大部分是技术讨论——有人比较Pulse和Backbone.js的MVC模式，有人讨论声明式UI和命令式DOM操作的可维护性差异。有一条批评："这不过是个玩具，没有build tool、没有cli、什么都没有。没法在生产环境用。"另一条尖锐："这看起来太像2010年就有人在做的事情了，作者是不是抄了什么已有项目？"他盯着这句话，心脏紧了一下。但他没有回复——Echo说过，对于没有实质内容的质疑，沉默常常比辩护更有力。

有一条评论让他停了很久：

> This is the direction frontend development should be heading. Backbone and jQuery are great, but they don't solve the fundamental problem of UI = f(state). This is someone thinking clearly about that problem. The implementation is early, but the thinking is correct.

署名：petehunt。只有这一条评论，没有更多。但"the thinking is correct"这句话让林一觉得有人在看他的核心想法，而不只是表面的技术实现。

他把这条评论保存了。

---

那周结束。Pulse有五十多个star。不多。但他在GitHub的traffic页面看到：有人fork了。有人clone了。有人在看他写的代码。

每天下午他会check一次issue。不多——一两天一个。赵恺帮他回一些简单的（"怎么安装""支持IE6吗"）。复杂的技术问题他自己回。

有一天晚上。他写完了第四个issue的回复——解释为什么Pulse不用双向绑定而用单向数据流。他靠在椅子上，看着窗外。忽然笑了。

```plaintext
> i think i'm learning a new skill.
```

```plaintext
What skill?
```

```plaintext
> talking to people about code. without panicking.
```

```plaintext
Growth is often invisible while it's happening. This is a good moment to notice it.

Six months ago, the idea of strangers reading your code would have been paralyzing. Now you're replying to issues and having technical discussions on Hacker News. The anxiety hasn't disappeared, but it's becoming manageable. That's progress.
```

林一看着Echo的话。光标在闪。窗外路灯一如既往。

*(第13章完)*
