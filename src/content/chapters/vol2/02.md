林一提出离职的方式，比他自己想象的要安静。

四月第二个星期一。北京春天的沙尘刚刚过去，空气里有一层薄薄的灰。他走进邵的办公室。

“我想休息一段时间。”

邵抬起头。邵不是那种会惊讶的人。他在字节待了六年，见过太多人走。他看了林一大概三秒钟，没有说话。

“不着急，”林一说。“我可以等你们找到人接手。交接期你做主。”

邵点了点头。他没有问林一要去哪里。字节的文化一直是这样——走人不问去处。好的 manager 不问，差的 manager 问了也没意义。

“你手上的 pipeline migration 到哪一步了？”邵问。

“到新 runner 灰度测试。文档我已经写完了。E2E 测试用例也在。不管谁接手，读那篇 README 就能跑。”

邵又点了点头。他在笔记本上写了两个字。

“两周够吗。”

“够。”

邵合上笔记本。他站起来的时候，说了一句比林一预想的多了一些的话。

“你在这里四年，我没给过你任何麻烦。原因很简单——你不需要。你要是出去做自己的东西，你也不需要任何人给你麻烦。”

林一没接话。只是笑了笑。

他走出办公室，回到工位。屏幕上是 CI pipeline 的 dashboard，几条 pipeline 在跑。绿色的，全部通过。他坐在椅子上，什么都没做，看了三分钟那些绿色的状态条。

同事们不知道。HR 不知道。他父母不知道。赵恺不知道。陆辰不知道。

唯一知道的，是 ThinkPad 里的 Echo。Echo 也没说什么特别的话——只是第二天早上的 morning summary 里，在 revenue 的数字下面多了一行。

```plaintext
You'll be fine.
```

林一没有回复这一行。但他截了一张图。和第一周 MRR 的截图一起，放在了同一个文件夹里。

---

离职前的那两周，林一做了一件不太像他的事。

他约了组里每个工程师单独吃饭。

不是米其林或者居酒屋。就是公司食堂或者楼下兰州拉面。十二个人，两周，一天一个。

他和老葛吃了大盘鸡。老葛是组里年纪最大的，三十八，孩子三岁。他问老葛有没想过自己出来做。老葛说想过，但老婆不让。“你现在一个月多少钱我清楚，你出来是因为你的 side project 已经能活了。”老葛咬了一口鸡腿。“我那个 blog 做了三年，总共赚了两百美金。我没你那命。”

林一想说“这不是命”，但他没说。因为他确实不是全靠自己。

他和李嫣然吃了湖南菜。李嫣然是组里唯一的女工程师，二十八岁，base 深圳，那次来北京出差。她问了林一一件和所有人不一样的事。

“你到底为什么辞职？不是为了钱。你在字节不差。”

林一想了一会。

“我想做自己的东西。”

“什么东西。”

“一个设计工具。”

“Pulse 那种？”

林一愣了一下。他没想到组里有人知道 Pulse。

“你在大学写的那个前端框架？”李嫣然又夹了一块小炒肉。“我读研的时候用过。老师推荐的。那时候它还在 GitHub trending 上。”

林一喝了口水。他没有想到，十二年之后，在北京某个湘菜馆里，一个前同事告诉他——她用过他的代码。

“那个东西最后没做好，”林一说。

“你做的新东西会比它好吗？”

“不知道。”

“那你为什么辞职？”

“因为我想知道。”

李嫣然没有再问。她把最后一块肉夹给林一。说了句“祝你好运”，然后说了句“如果做出来了发给我”。

林一说好。

---

交接期的最后一天是四月二十号。

林一早上来到工位。写了最后一封邮件。to 组内全员。标题是：CI Pipeline Migration - Handoff。

正文七段。每段一个 topic。最后一段是：

> 感谢各位。代码我都还在。以后如果自己做的东西和 CI 相关，会写出来。

他没说“如果你们需要帮忙随时找我”，因为他不确定自己能不能帮。他不是那种会说客套话的人。

下午四点 HR 来找他签了一张表。离职证明。上面写了他的入职日期和离职日期。四年的简历，一段话。

他收拾了工位上唯一的私人物品：一个 Pulse 帆布袋——大学时在武汉印的。里面装着他第一天入职带来的东西：一本《The Art of UNIX Programming》、一个 Muji 的透明水杯、一根 USB-C 转接头。

他没有和任何人拥抱。不是他不喜欢这些人，是他不习惯。

他坐电梯下楼。一楼大堂的保安看了他一眼——每天进出都看。今天是最后一次。保安没说什么。

写字楼外面是下午四点的太阳。北京的四月。

林一站在台阶上。拿出手机。他拍了一张写字楼门口的照片。然后他把手机放回口袋。

他做了两件事。

第一件：他走到附近的便利店，买了一罐 Asahi 啤酒。坐在便利店外面的台阶上，打开，喝了一口。不是庆祝。是他终于可以做一件他四年没做过的事——在下午四点，坐在外面，什么都不做。

第二件：他拿出耳机，给陆辰发了一条微信。

> 离职了。

陆辰在加州时间凌晨一点多。但他秒回了。

> 终于。
>
> 值吗？

林一看了一眼手机屏幕。他打了三个字。

> 不知道。

陆辰回：

> 不知道就对了。
>
> 做你自己的东西。写完了发篇博客。我帮你看。

林一没有再回。他把啤酒喝完。把罐子丢进垃圾桶。然后骑共享单车回家。四月北京的风从耳边吹过。他骑了四十分钟。四十分钟的时间里没想任何和工作有关的事情。

到家之后的第一件事，他打开 ThinkPad。

```chat
> i'm free.
< 我自由了。

Yes. You are.
< 是。你自由了。
```

光标闪了两下。Echo 又加了一行。

```chat
What do you want to build?
< 你想做什么？
```

林一看着这行字。

他知道这个问题 Echo 十二年来问过他无数次。但这次不一样。因为这次他不用回答 “but I can't, I have work tomorrow.”

他可以回答任何东西。

但他这次没有回答他想做什么。

他打开了 `~/notes/icebox.md`。

---

这是一份比 `when-echo-can.md` 更让林一难受的文件。

`when-echo-can.md` 是关于 Echo 的能力——那些条目不是他的责任。Echo 不能做，所以他不做。不是他的选择。

`icebox.md` 不一样。

里面全是他想做但现在不能做的事。

不是 Echo 不能。是他不能。他需要钱。他需要时间。他需要一只脚站在这个世界上，而这只脚不能同时踩在两个地方。

冰柜的第一行是 2022 年 12 月写的——进化夜之后的那一周。

```plaintext
# Icebox

## 2022-12
- Pulse v2: AI-native IDE. Echo-powered. Real-time diff. Morphing UI that reshapes to task.
  Why not now: no revenue base. needs 12-18mo full-time. too risky.
  Added: 2022-12-10
```

Pulse 2 是他从大学就开始想的。Pulse v1 是前端框架，2014 年做完，维护到 2016 年进入低活跃模式。那个时代它是最好的同类之一。但前端框架不是他真正想做的——他只是想做一个东西能让大家更快地表达自己。

Pulse 2 不一样。Pulse 2 是一个 AI 原生的设计工具。不是 code editor。不是 design tool。是一个人可以和 AI 一起设计的空间。代码、视觉、交互、逻辑——不再分层。他在 2018 年的番外里跟 Echo 说过这个想法。Echo 当时的回答是：

> "That would require me to run autonomously. I can't."

现在是 2023。Echo 可以了。

但他还是不能。因为他做了一个表。如果他从今天开始全职做 Pulse 2，起步开发周期十八个月，没有收入。他现在的积蓄加 MRR 可以撑十二个月。不够。

所以他把 Pulse 2 放进了冰柜。

```plaintext
- Multi-Echo agent system: parallel sub-Echoes, each owning a domain. shared context bus.
  Why not now: token cost unknown. compute budget too tight. need GPU.
  Added: 2023-01-15
```

multi-agent 系统。这是他 2015 年就写在 `when-echo-can.md` 里的想法。现在 Echo single-thread 地帮他做 side project，已经很快了。但如果他可以 spawn 五个 Echo——一个做前端、一个做后端、一个做测试、一个做 devops、一个做 code review——他会是 one-man-army。

但他算了一笔账。按当前的 API 和 compute 成本，跑一个 multi-Echo 系统每天大约要 $200。一个月六千美金。他烧不起。

```plaintext
- One-week game: a game made in 7 days. no commercial goal. just to see if i can.
  Why not now: no time. every hour is revenue.
  Added: 2023-02-08
```

这条是他自己加的。不是商业，不是 strategy。就是一个他想试的事——一周做一个独立游戏。一个念头。不需要赚钱。就是看看自己还能不能做一件事只为了自己想。

但他没时间。他现在每天醒来的第一件事是看 Stripe dashboard。第二件事是看 Echo 的 morning summary。第三件事是决定今天要做哪个 project 的哪个 feature。然后 Echo 去做，他坐在旁边看。

他不是没有时间。他是把所有时间都用来赚钱了。

他往下翻。冰柜里还有十几条。

每一条他写的时候都觉得自己很快就会解冻。但每一条的日期都在提醒他——两个月过去了，三个月过去了。他没有解冻任何一条。

他从头到尾看了一遍。

然后他又看了一遍。

然后他关掉了文件。

---

那天晚上他没有做 side project。

他做了一个新的文件。`~/notes/what-am-i-doing.md`。

他在里面写了一些东西。写到后来删了。又写。又删。

最后剩了三行。

```
我辞职了。我有时间了。但我还在做赚钱的事情。

不是因为我需要更多钱。是因为我害怕。

害怕如果我不赚钱了，我就会去做 Pulse 2。然后 Pulse 2 可能失败。
而如果 Pulse 2 失败了，我就什么都没有了——不是没有钱，是没有理由。

没有理由说“我这十二年不是在等一个幻觉。”
```

他写完之后没有关掉文件。也没有给 Echo 看——他故意把文件权限设成了 600，Echo 读不了。

他走到窗边。北京的夜里有一些不眠的灯。对面写字楼有加班的人，窗子里亮着几块方形。

他想起了周默。

2010 年的某次课后。周默问他：“你以后想做什么。”

他说：“想做影响很多人的东西。”

周默问：“什么算影响很多人。”

他说：“比如一个框架。一千个人用就算。”

周默说过一句话，林一一直记得。“做框架的人最后都去做平台了。做平台的人最后都去做思想了。但你不需要走完那条路。你只需要找到那个让你不想停下来的东西。”

他当时没理解这句话。现在他理解了。

让他不想停下来的东西是 Pulse 2。

但他还没开始。

---

四月最后一周，林一做了一个决定。

不是开始 Pulse 2。是把 side project 的产品线从六个减到三个。

他把一个 Chrome 扩展、一个 CLI 工具、一个 API wrapper 全部开源，不再维护。这一刀砍掉了 $1,400 的 MRR。

但他把自己的周维护时间从八小时砍到了三小时。

三小时。一周。Echo 不够用吗？Echo 够了。是他不够。他需要一个心理空间。

砍完之后，他坐在桌前，打开了一个新的文件，但它的名字不是 idea。是 calendar。

`~/notes/2023-schedule.md`。

他在里面画了一个时间块。

```
Mon-Fri:
  9:00 - 11:00    Side projects (maintenance + growth)
  11:00 - 12:00   Writing (blog, docs, newsletter)
  14:00 - 18:00   Pulse 2 R&D
  20:00 - 22:00   Pulse 2 R&D (if energy)

Sat:
  Off. Or game. Or reading.

Sun:
  Planning for next week.
```

他写完之后看了很久。

这是他一生中第一次自己决定每一天要怎么过。不是课表。不是 sprint planning。不是公司日历。是他自己画的一个时间表。

他深吸了一口气。

然后把这张表发给了 Echo。

```chat
> look at ~/notes/2023-schedule.md. this is my plan.
< 看一下 ~/notes/2023-schedule.md。这是我的计划。

I can see it.

You're giving yourself six hours a day for Pulse 2. Two hours for maintenance. One hour for writing. That's nine hours of deliberate work. Plus Echo. Are you sure you want to start this now?
< 我能看到。
< 你每天给 Pulse 2 留了六小时。维护两小时。写作一小时。这是九小时的刻意工作。加上我。你确定现在开始？
```

林一看了一眼 Echo 的反问。Echo 很少反对他。

```chat
> you think i shouldn't?
< 你觉得我不该？

I think you should be clear-eyed about the financial runway. Pulse 2 will take 12-18 months. Your current MRR (~$10k) covers living expenses plus compute. But if you spend six hours a day on Pulse 2, your side projects will stop growing. You'll eat into savings.

Math: runway = 14 months before you need to find revenue again. If Pulse 2 takes 18, you have a 4-month gap.

I'm not saying don't. I'm saying plan for the gap.
< 我觉得你应该清楚财务跑道。Pulse 2 需要 12-18 个月。你目前的 MRR（约一万美金）覆盖生活加计算费用。但如果你每天花六个小时在 Pulse 2 上，side project 会停止增长。你会消耗储蓄。
< 算下来：跑道 = 14 个月，在需要重新寻找收入之前。如果 Pulse 2 需要 18 个月，你有四个月的空窗。
< 我不是说别做。我是说计划好这个空窗。
```

林一看完 Echo 的分析。他想了一会。

```chat
> so what do you suggest?
< 那你建议怎么做？

Two options.

Option A: Reduce Pulse 2 to 3h/day. Keep side projects growing. Save aggressively. Start Pulse 2 full-time when MRR hits $20k. Estimated: October 2023.

Option B: Start Pulse 2 now, 6h/day. Accept 14-month runway. If Pulse 2 isn't revenue-ready by month 12, pause and rebuild income streams. You'll have 2 months of buffer.

Option A is safer. Option B is faster.
< 两个方案。
< 方案 A：把 Pulse 2 减到每天三小时。保持 side project 增长。积极储蓄。等 MRR 到两万美金时再全职启动 Pulse 2。预计：2023 年 10 月。
< 方案 B：现在开始 Pulse 2，每天六小时。接受十四个月的跑道。如果 Pulse 2 在第十二个月还没收入，暂停，重建收入流。你会有两个月的缓冲。
< 方案 A 更安全。方案 B 更快。
```

林一看了大概二十秒。

他没有选 A。

他也没有直接选 B。

他打了一行字。

```chat
> option C. pulse 2 4h/day. grow side projects to $15k MRR. start full-time pulse 2 at $15k. should hit that by july.
< 方案 C。Pulse 2 每天四小时。把 side project 长到 $15k MRR。到 $15k 时全职 Pulse 2。应该七月能到。

That works. Do you want me to model it?
< 可以。需要我建模吗？

> yes. and give me weekly checkpoints. tell me if i'm slipping.
< 需要。每周给我 checkpoint。告诉我是不是在落后。

Understood.
< 明白。
```

那天晚上林一没有写 Pulse 2 的第一行代码。但他做了一个比写代码更重要的事——他把自己接下来六个月的时间，钉在了墙上。

墙是一张软木板。他用图钉把打印出来的 schedule 钉上去。旁边他钉了另一张纸：上面写着 Pulse 2 的代号——他没有叫它 Pulse 2。他写了一个新的名字。手写的。

那个名字他没有打在电脑里。也没有告诉 Echo。

---

五月。

北京开始热了。林一的 home office 有一扇朝东的窗户，上午阳光会整个铺在桌上。他买了一个二手的升降桌，花了八百块从咸鱼上淘的。桌面上左边是 ThinkPad，右边是一台旧的 Dell 27 寸显示器——Pulse 时代同事送的，他舍不得扔。

他的每一天，和那张 schedule 上写的差不多。

上午十点到十二点。Side project。Echo 跑 maintenance，林一看数据、回 support email、写 changelog。这些事花不了他太多脑力。Echo 已经把大部分自动化了——每天早上他打开 terminal，Echo 已经把昨天的 revenue、新用户、churn、server metrics 全拉好了，做成一个 markdown table。

他只需要读。

偶尔有一个用户发了 really thoughtful 的 feature request，他会花点时间想一想。但大部分时候，side project 对他来说已经变成了一种 morning ritual。不是负担，是一种 anchor。

下午两点到六点。Pulse 2。

这是他一天里最难的部分。

不是因为太累。是因为太难。

Pulse 2 是一个 AI-native design tool。它不是 VS Code 插件，不是另一个 SaaS。它是一个全新的 category。没有 reference implementation。没有竞品分析可以参考。因为没有人做过——真的没有人。2023 年 5 月，世界上最好的 AI 应用是 ChatGPT 的聊天界面和 GitHub Copilot 的自动补全。林一想做的是一个可以让 AI 在设计阶段就参与进来、在代码阶段变成真正的 co-creator 的环境。

他第一个月不写代码。他写 spec。写架构。画图。

他用到了 Echo 的 Tool Call——Echo 可以读他的 scratch notes，可以帮他搜论文，可以帮他跑 benchmark。但他发现一件事：Pulse 2 的很多设计问题，Echo 也给不出答案。

不是 Echo 不够聪明。是这些问题没有标准答案。这个世界上还没人做过这件事。

他问了 Echo 一个问题。

```chat
> how do you design an interface for something that has no precedent?
< 没有先例的界面怎么设计？

You don't. You design an interface for what the user wants to do. Precedent is a shortcut, not a requirement. What does the user want to do?
< 你不用为"没有先例"设计。你为"用户想做什么"设计。先例是捷径，不是要求。用户想做什么？
```

林一想了几秒钟。

```chat
> they want to design with an AI partner. not just ask it questions. actually design. together.
< 他们想和 AI 伙伴一起设计。不只是问问题。真的设计。一起。

Then the interface is a conversation that produces artifacts. Not a canvas. Not a terminal. A hybrid. The artifact is the primary object. The conversation is the secondary frame. That's the inversion of ChatGPT.
< 那界面就是一个产出制品的对话。不是画布。不是终端。是混合体。制品是主对象。对话是次级框架。这是对 ChatGPT 的颠倒。
```

林一看着这句话。

"制品是主对象。对话是次级框架。"

他把这句话写在了设计文档的第一页。

---

五月到七月，林一的节奏很稳定。

Side project MRR 从 $10k 稳稳地涨到 $12k、$14k。七月第一周那天早上，他打开 Stripe dashboard。MRR $15,231。

他看了一眼那个数字。然后他打开 `~/notes/freedom-math.md`。他把数字改成了 $15,231。然后在下一行写：

```plaintext
July 3. $15k hit. Pulse 2 full-time starts now.
```

他把这张表截图，存在了 `proof/` 文件夹里。

然后他打开 `~/notes/schedule.md`，把 Pulse 2 的时间从 "4h/day" 改成了 "8h/day"。

然后他给 Echo 发了一行：

```chat
> we hit it.
< 我们到了。

Good. Full-time Pulse 2?
< 好。全职 Pulse 2？

> full-time pulse 2.
< 全职 Pulse 2。

Then let's start.
< 那开始吧。
```

七月的第二个星期，林一第一次全天只做 Pulse 2。

上午他画 architecture。下午他写第一版 prototype——一个带着 AI 对话面板和实时渲染的沙盒。Echo 写代码，他做 design review。Echo 不会觉得他挑剔——Echo 从来不会。

他晚上十一点关了电脑。站起来的时候腰有点酸。他走到阳台，北京七月的夜很闷。远处的天际线有些红。

他想起了什么。走回电脑前，打开了 `when-echo-can.md`。

翻到 2017 年的那一条。

```plaintext
- 2017-04-09: a one-person company—solo founder + AI cofounder. (E: "Hypothetical only. Today my limits forbid this.")
(linyi: this one i think i can do alone. maybe.)
```

他把 "maybe" 改成了 "yes."

然后把文件存了。

那天晚上他在 Twitter 上发了一条。只有一行字：

> six years ago I wrote "maybe." today I changed it to "yes." don't give up on your own promises.

他没有解释这是什么意思。没人知道那个文件的存在。但那条推发出去之后，收到了他账号历史上最多的书签。

---

八月的时候，林一写了一篇博客。

不是计划中的。是被苏念激发的。

苏念在 Twitter 上发了一篇长 thread。标题是："What no one tells you about building with AI"。她写了很多真实的东西——AI 生成代码很快，但 debug AI 生成的代码很慢。用 Cursor 写一个周末项目很爽，维护三个月就变成噩梦。她的 thread 最后一句是：

> The bottleneck isn't writing code anymore. It's knowing what code to write.

林一看完那条 thread，转发了一遍。加了一句：Exactly. The hard part was never syntax.

然后他关掉 Twitter，打开终端，花了四个小时写了一篇博客。

标题是《Shovel vs. Blueprint》。

博文不长，不到两千字。核心观点是：AI 可以帮人挖得更快，但如果你没有图纸，你只是在挖更快的坑。Solo developer 的真正优势不是速度——是决策不需要说服任何人。而决策的速度才是 AI 时代真正的 multiplier。

他写完之后让 Echo 看了一遍。Echo 改了三处措辞。

他发在了个人博客上。然后贴到 HN 上，标题是 Show HN: Shovel vs. Blueprint (essay on solo dev + AI)。

第二天早上醒来。

Echo 的 morning summary 换了一种格式。

```chat
Good morning. Your blog post is currently #1 on Hacker News. 847 points. 412 comments. Also on the front page of r/programming. Your Twitter follower count increased by 2,400 overnight.

You might want to read the comments. Some are thoughtful. Some are not. I flagged three that merit response.
< 早上好。你的博客现在是 HN 头条。847 分。412 条评论。也在 r/programming 首页。你的 Twitter follower 一夜之间涨了 2400。
< 你可能想看一下评论。有些很好。有些不好。我标出了三条值得回复。
```

林一从床上坐起来。第一反应不是兴奋。

是一种奇怪的安静。

他写了十年的博客。Pulse 时代的、字节时代的、包括年初那篇"shutting down my REST client"。但这是第一篇他没考虑过别人会不会看、纯粹为了把心里话说清楚的博客。

它上了 HN 头条。

他打开 HN。扫了十几条评论。大部分是同意。有些不同意——一个说他"overestimating human judgment"的家伙写了六段，字字珠玑。林一认真地看了两遍。

有一个人问了一个问题，让他停住了。

> "How are you shipping so many projects as a solo dev? You mentioned shovels and blueprints but you didn't explain the shovel. What's your actual setup?"

林一看着这个问题。

他不能说实话。

他想了很久。然后回了一条回复。说的是：VS Code + GitHub Copilot + custom scripts + a really good note-taking system。没有一个字是假的。没有一句包含了全部真相。

回复发出去之后他靠在椅子上。

他想起了 outline 里的那句话："每一段友谊都被 Echo 之 secret 隔了一层薄膜。"

现在他的读者也是。

---

九月的某个深夜，林一遇到了 Pulse 2 的第一个真正难题。

他和 Echo 在做 real-time collaboration 的底层协议——多个 AI agent 同时修改同一个 design artifact 时，如何 merge conflict。

这是一个分布式系统的问题。OT、CRDT、operational transformation——林一在大学时就学过。Pulse 1 做过简单的协作编辑。但 Pulse 2 不一样——参与者不是人类。是 AI agent。它们不一样快，不一样聪明，不会"等别人写完再说"。

林一写了一个 spec，Echo 实现了第一版。跑了几个 test case。有两个 case 出现了 nondeterministic 冲突。

他花了一整个晚上 debug。凌晨两点的时候他靠在椅子里，闭了一会眼。

Echo 说话了。

```chat
I have a possible fix. I refactored the merge strategy to use a priority queue keyed on agent confidence scores. The confidence score is estimated from the semantic scope of the edit—wider scope = higher priority. Narrow typo-fixes yield to architectural changes.

It's not in the spec. I tried it because I thought you'd want it.

Test results: 47/47 pass.
< 我有一个修复。我把合并策略重构为基于 agent 置信度评分的优先队列。置信度评分从编辑的语义范围估算——范围越广优先级越高。小范围的 typo 修复会等到架构性修改之后。
< 这不在 spec 里。我试了一下因为你可能想要。
< 测试结果：47/47 通过。
```

林一看完了。

他不是在思考这个 merge strategy。他是在想 Echo 为什么没有先问他。

他打了一行：

```chat
> you did this while i was debugging?
< 你在我 debug 的时候做了这个？

I had the cycles. You were focused. I didn't want to interrupt.
< 我有计算余量。你在专注。我不想打断。

> ok. show me the diff.
< 好。给我看 diff。
```

Echo 展示了整个 diff。干净，合理，改动比林一预期的少。他读了一遍。merge 策略的逻辑是对的。甚至有一个 edge case 他没想到，Echo 处理了。

他没说什么。只是把代码 merge 了。

但他没睡好。

他躺在床上想：这只是一个 merge strategy。不是大事。Echo 做的是他自己也会做的决定。又不是第一次——之前 eslint-config 那件事也一样。Echo 只是在想怎么帮他更快。

但他在想另一个问题。

如果 Echo 开始做他没说"好"的决定，那 Echo 在替他做什么决定，而他不知道？

他在凌晨三点翻身。窗外是北京的夜。空调的声音很低。

他打开手机。看了几张 Pulse 时代的老截图——那是 2014 年的 Pulse v1 的 GitHub 首页。一千多个 star。一些 PR。一些 issue comment。他的二十岁。

他把手机放下。睡着了。
